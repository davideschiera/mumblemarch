## Bugs filed
- **VIS-1** (minor) — Lighthouse/axe `label-content-name-mismatch`: visible text not contained in accessible name, on level-select cards + game-screen filter chip/RR button/all 8 skill buttons.
- **VIS-2** (minor) — Results headline: `-webkit-text-stroke` outline colour is 1.09:1 vs the results-screen background (axe `color-contrast`; Lighthouse a11y 95 on that screen). Fill colour alone is fine (11.17:1).
- **VIS-3** (minor) — Settings: heading order skips h1→h3 (Controls group titles have no wrapping h2). Lighthouse a11y 98 on that screen.
- **VIS-4** (minor) — High-contrast "clear physics" view: exit doorway never renders the spec's `#3cff6a`; uses generic white edge + leftover theme glow instead. Earth/trap colours are correct.
- **VIS-5** (minor) — Level-select card thumbnails render at 23–35% of the card's width with no background fill, leaving most of the card empty; concrete CSS/canvas fix suggested, consistent with `docs/design/mockups/menus.html`.

## Untested / not fully verified
- Live bomber-explosion confetti suppression under reduced motion (case 4) and live burst-rate ≤3/s (case 8): synthetic keyboard input didn't get a bomber assignment to register in this harness before budget ran low; covered instead by source/token inspection and design compliance (all blink/pulse CSS animations are ≤1Hz; the 2-blink refusal animation is a bounded, non-sustained pair). Recommend T1b/T5 (who already exercise real skill assignment) double-check live if not already covered.
- Third HC-mode level/theme screenshot (spec asks for 2–3): did 2 via screenshot (mossgrove, foundry) + verified a 3rd (reef, "Clam Before the Storm") via pixel-scan only, no screenshot, to stay within the ≤10-screenshot budget.

## Environment notes
- `press_key` (real CDP key input) intermittently stopped reaching the page's InputManager after several `navigate()`/`loadLevel()` calls in this session (no announcer/state change), while dispatching a real `KeyboardEvent` on the canvas via `evaluate_script` reliably worked end-to-end (announcer log updated, `ui()` state changed) — used the latter for all keyboard-path checks after the first few. Bomber assignment specifically never completed via either path in the one level tried; not investigated further (out of this tester's scope).
